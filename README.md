# 声场 · Sound Atlas

将二层工作室的声环境放回真实空间：CAD 平面、可旋转三维模型、五张公桌与个人工位 D2 的声级、噪声热力图与采集管理。

**[打开网站](https://www.alecyin.icu/sound-atlas/)** · **[采集管理](https://www.alecyin.icu/sound-atlas/collect/)**

展示页面可公开访问。采集管理需要所有者的私有管理口令，口令不在此仓库中。

## 功能

- CAD 平面与等角三维空间；真实位置的墙体、门窗和家具。
- 六个声级测点、半小时等效声级、历史回放和变化曲线。
- 平面及三维热力图、右侧竖向图例，默认强度 75%。
- 明暗主题、随三维镜头旋转的指北针、移动端布局。
- 自动同步实测摘要；无数据及离线状态明确提示，演示数据需主动选择。
- 实时采集面板：六个测点的大字号最新 1 秒声级、近 5 分钟曲线、数据年龄和故障状态；页面每 1 秒检查、管理同步目标间隔 1 秒（网络耗时另计）；累计统计每 5 秒刷新，设备仍约 30 秒批量上传。
- 数据管理按“筛选 → 曲线 → 处理”组织：精确选区、范围内记录统计、可用/原始 CSV 导出、异常定位与可撤销排除；未应用的新筛选不能用于修改或导出。
- 站内采集计划和备份后删除保留，永久删除单独收纳并二次核对。

## 本地预览

需要 Node.js 22+ 与 Python 3.10+。静态页面无打包步骤：

```sh
python -m http.server 8080 --directory dist
```

访问 `http://localhost:8080/`。静态预览可查看模型和主动切换演示数据；实时数据与采集管理依赖下面的服务端配置。

## 部署网站与接口

1. 将仓库导入自己的 Vercel 项目，根目录保持仓库根目录。`vercel.json` 已配置 `dist` 和 `api`。
2. 配置支持 REST API 的 Upstash Redis，添加以下私有环境变量（参见 `.env.example`）：

   | 名称 | 用途 |
   | --- | --- |
   | `KV_REST_API_URL` | Redis REST 地址 |
   | `KV_REST_API_TOKEN` | Redis REST 写入凭据 |
   | `SOUND_ATLAS_INGEST_TOKEN` | 采集端与云端共享的随机同步密钥 |
   | `SOUND_ATLAS_ADMIN_KEY_HASH` | 管理口令的 SHA-256 十六进制摘要 |

3. 为自己的实例创建随机同步密钥和独立管理口令。管理页面输入原始管理口令，服务端仅保存其摘要。不要复用本项目线上实例的密钥。
4. 新域名或反向代理部署时，核对 `lib/admin-auth.mjs` 的可信来源设置，并更新页面中指向原站点的链接。
5. 发布后访问 `/` 与 `/collect/`。现有线上实例挂载在 `/sound-atlas/` 下，资源和接口使用相对路径。

GitHub 仓库提供源代码；GitHub Pages 只能承载静态部分，不能单独运行采集管理和这些服务端接口。

## 启动本机采集端

```sh
cd collector
python receiver.py
```

本机界面为 `http://localhost:8000/`，采集计划在 `/control`，数据管理在 `/manage`。Windows 也可使用本目录内的启动、停止 PowerShell 脚本。

设备继续通过本机服务的 `/upload` 上传，使用 `/config` 与 `/time` 同步计划和时间。此仓库包含接收端，不包含硬件固件。

启用云端同步：复制 `live_bridge_config.example.json` 为 `live_bridge_config.json`，将 `enabled` 设为 `true`，填写自己的 `/api/ingest` 地址和与云端一致的同步密钥。此文件已被 Git 忽略。

原始数据保存在本机 SQLite；采集端主动向云端同步摘要并拉取经过认证的管理指令，不需要将本机端口公开到互联网。采集电脑需要持续运行并联网。

## 数据与模型说明

- 半小时等效声级按声能平均计算；热力图是测点插值估计，并非考虑墙体传播的声学仿真。
- 平面位置依据 CAD；模型墙高 3.2 米及门窗、家具的竖向尺寸为展示设定，未作为实测建筑尺寸。
- 不包含原始采集记录、数据库、备份、部署凭据或管理口令。实际运行数据不随源码发布。
- 字体、Three.js 和材质的来源及许可见各资源目录中的许可文件。本仓库公开可读，不额外授予未声明的资源许可。

## 五分钟相对校准

在采集管理的“五分钟校准”页操作。全部六块板子（N1、N2、N3、N5、D1、D2）在线、对时且麦克风正常后，把麦克风并排、同高同向。点击开始并确认：45 秒准备、300 秒采集、45 秒等待末批上传。此操作暂时替换全局采集计划；校准时段自动标记排除于日常分析，原始记录保留。校准结束后先检查报告，板子放回各自位置后手动恢复原采集计划。

仅取本次六块都有有效读数的共同秒。每秒参与设备的中位数为相对参照，每块修正量为这些秒中“参照减本板原始LAeq”的中位数。最低 240/300 共同有效秒是本工具的完整性门槛，并非计量标准。报告提供修正前后相对 RMSE、残差 MAD 和异常提示；它是同组数据回算，不是独立验证。

应用后仅对应用时间之后的 LAeq 使用版本化偏移；原始数据库不改写，倍频程频带与 LAFmax 不修正。实时面板和空间展示使用适用修正，数据管理曲线仍是原始读数。“导出相对校正记录”另加 `laeq_corrected`、`correction_db`、`calibration_id` 列。停用只停止之后的修正，历史版本保留。

没有参考声级计时，只能相对对齐；不能据此声称绝对声级已校准。关于已知参考源校准，可参阅 [NIOSH 声级测量应用说明](https://stacks.cdc.gov/view/cdc/137474/cdc_137474_DS1.pdf)。

设备位置变更由 `collector/node_locations.py` 按时间记录。N4 与 D1 互换后，校准仍跟随原设备编号；历史观测不会被重新放到新位置。数据管理按设备查询，空间展示按采样时刻的位置聚合。

历史布点：D2 与 N4 再次互换后，D2 在个人工位、N4 在宿舍；D1 仍在公桌 B。两次交换各有生效时间，旧观测仍按当时位置归属。

## 持续采集

采集计划页选择“持续采集”，点击启动，无需填写时间。未在记录时预留约30–40秒统一开始；正在定时记录时保留原开始时间并清除结束时间，直到手动停止。关闭网页不会停止已生效的计划。没有生效计划时，当前板子程序不生成新的观测记录，但已有缓存仍可以上传。离线停止必须等设备重新连接并收到指令；板端掉电后的计划/缓存恢复取决于实际烧录的固件版本。

时间轴支持连续拖动与平滑播放。分钟级指针用于浏览，数据仍是所在半小时的实测统计，不增加数据时间分辨率。有效热图之间采用180毫秒视觉渐变，缺少有效测点的时段立即留空；热图缓存、固定几何权重和动画帧合并降低重复绘制开销。

数据管理默认自动跟随已收到的新记录：查询结束时间、曲线和条数同步推进。当前计划曲线及每节点计数预先生成、按修订版本上传；切换测点无需重复远程查询。自定义范围使用只读组合查询，曲线和计数一起返回。编辑时间、选区或导出/排除会暂停跟随并锁定操作范围，支持手动恢复跟随。新记录的到达频率仍受设备上传间隔限制。

当前已停用宿舍 N4，仅保留六个二层测点。原始 N4 记录与既有七板校准不删除、不重算；新校准使用单独保存的六设备参与名单，旧任务仍按原七设备解释。导出保留毫秒时间戳，可按时间戳对齐分析。
